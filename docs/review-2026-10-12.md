# Review of 12 October 2026: what was found, what was done

A review of the engine, the interface, the model of site B, the deployment and
the documents, done by reading the code (nothing was run by the reviewers).
Findings were checked and ranked, then fixed in order of what they could cost.
This list says where each one stands, so that what was left is a decision and
not something forgotten.

## Closed

| Finding | Where it was closed |
|---|---|
| A tunnel token was committed in `docs/deploy.md` | Removed; the token was rotated. The old commit still holds the (dead) value. |
| Any environment variable could be sent to any URL | ADR 0024: only names like a key, in the schema and when read |
| The API key followed a redirect to another host | ADR 0024: redirects are not followed |
| Cloud metadata and link-local addresses could be called | ADR 0024: refused, ranges set in `settings.php` |
| Credentials in a URL or in headers could be stored | ADR 0024: refused by the schema, left out of messages |
| The local cluster listened on every interface with public passwords | Bound to 127.0.0.1 |
| The DDEV host was trusted in production | Only when `IS_DDEV_PROJECT` is set |
| A dead item of an older run could undo a later run, or lower its mark | ADR 0025 |
| An entity deleted by hand was never made again | ADR 0025 |
| A changed target was not noticed, and the ID of another type was reused | ADR 0025 |
| A claim could run out while a worker still held its items | ADR 0025: the claim is renewed |
| Cancelling did not reach items a worker already held | ADR 0025 |
| Extraction could write an old position over a new one | ADR 0025 |
| A taken ID could be saved from a new import by leaving step 1 by the menu | The save checks it, and the step menu shows it |
| A disabled import could be started by a request without the button | The form and the run starter check |
| `view import runs` was not a restricted permission | Restricted |
| The dead letter handlers relied on a hidden button; a pending item could be edited | Each handler checks the permission; only dead or retrying items are edited |
| A path from the source could be shown as markup in a button | Escaped |
| Links to pages that answer "access denied" | Operations are shown only when the person may use them |
| The order widget of a run set ran out of weights; a missing import vanished silently | The widget has room for the rows; a missing import stays on its row, marked |
| Editing or deleting an unpublished account, item or agreement by its address | Only administrators, as for viewing |
| No update hook for the unique keys of site B | `site_b_catalog_update_10001` (run `drush updatedb`) |
| The cascade of agreements could loop for ever | It stops with an error when a pass changes nothing |
| `bootstrap.sh` never imported configuration on an installed site | It does now, and runs the updates |
| The containers ran as root | Apache on 8080 as `www-data`, drush and the jobs as user 33, no privilege escalation, no capabilities (tried in k3d) |
| Every pod got the whole secret, the root password of MariaDB included | One secret per workload with only what it needs (checked: the web pod has no root or admin password, the worker has no site A secrets) |

## Open, on purpose

- **No NetworkPolicy**, and `REVERSE_PROXY_ADDRESSES` trusts all of 10.0.0.0/8.
- **`bootstrap.sh` is not safe after a partial failure** of the install (the
  "installed" check is the bootstrap level of Drupal, and the seed check treats
  an error as "no data").
- **The image workflow does not wait for CI**, and some images are not
  pinned to a version.
- **Rows of a deleted import are left** (mapping, pages, items), and the
  mappings of items that left the source under the unpublish policy are kept.
- **The wizard overwrites a change made elsewhere** to an import that is being
  edited (it saves the whole snapshot).
- **Several tests only cover the happy path** for the screens of definitions,
  connections and settings (route access is tested for runs, the dead letter
  queue and the breakers).
- **A response size limit and `Retry-After`** are not handled by the HTTP
  source.
- **The demo account sees item keys and error text** of runs; the errors are
  made to leave out query strings and credentials, but nothing scrubs every
  possible message.
